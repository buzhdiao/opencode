# OpenCode 原理性介绍 · 总目录与全仓导读

> 本目录（doc_zh/原理介绍/）是一套面向"理解设计原理"的中文长文，共十八章正文加一篇总目录。它不再停留在"这是什么"的层面，而是系统回答三个更难的问题：OpenCode 为什么被设计成这样、每一层机制在数学或工程上如何运转、以及这些取舍付出了什么代价、换来了什么。全部技术事实以当前仓库（dev 分支）的真实代码为准，引用一律给出真实文件路径与函数名；凡属推理、推断或方法论展开的内容，文中均明确标注，不与事实混写。

## 一、OpenCode 是什么，本套文档怎么读

OpenCode 是一个开源的 AI 编码 agent（AI coding agent）。它以终端为主要形态，同时提供 Web 界面与 Electron 桌面应用，三种形态共享同一个后端内核。用户用自然语言描述目标，系统驱动一个大语言模型在真实代码库上循环执行"读代码—改代码—跑命令—观察结果—再决策"，直到任务完成。与"编辑器内补全"或"对话框问答"不同，agent 形态的产品把"执行"也交给了模型：它不只是建议代码，而是亲手使用工具完成修改，因此整套系统的设计重心从"提示词"转移到了"执行环境"——如何让模型安全、可靠、可恢复地操作一个真实工程，这恰是本套文档的主线。

从仓库形态看，OpenCode 是一个 Bun workspaces 加 Turborepo 的 monorepo。根 AGENTS.md 明确约束了运行时依赖方向：schema 定义一切跨进程契约，core 承载领域行为与持久化，server 把 core 装配成 HTTP 服务，protocol 用 effect 的 HttpApi 声明公开端点，client 由协议生成，sdk 把 client、core、server 组合成可编程形态；tui、app、desktop、cli 则是三种用户形态加命令行入口。这个分层不是"为了好看"，而是由一个硬需求倒逼出来的：同一个会话必须能同时被终端、浏览器与桌面观察到并保持一致，于是业务逻辑只能写一次，放在一个与前端无关、与传输无关的内核里，其余各层围绕它做投影。第一章到第十八章将沿着这条主线逐层展开。

阅读建议按依赖顺序：先读第一章建立"agent 循环"的思维模型，再读第二章掌握整体分层；第三、四、五章构成"会话引擎"三部曲，是全书核心；第六、七、八章覆盖"工具—模型—权限"这个执行三角；第九、十、十一章讲可扩展性与传输面；第十二、十三章讲前端与外围机制；第十四章收束于质量保障、构建发布与整体复盘；第十五至十七章是三个工程横切面（性能、诊断、生态），可以在前十四章之后作横向总结阅读；第十八章以六个实战场景把全部机制串成时间线，作为全书的收束验证。每章独立成篇，可以按需跳读，但三章以上的连续阅读会得到一条完整的因果链。

## 二、各章摘要

### 第一章 · AI 编码 agent 的本质与 agent 循环
从"补全—对话—代理"三代范式的演进讲起，论证 agent 的形式化定义：以 LLM 为决策器、以工具为执行器、以循环为控制流的图灵机式构造。给出 agent loop 的抽象状态机（规划—行动—观察—再决策），讨论终止性、步数上限与 token 经济学，解释"终端"为何是最适合 agent 的全景接口，并落到 OpenCode 的循环实现——SessionRunner 的 drain 主循环与 LLMEvent 流。本章是全书的公理层，后续所有机制都可以还原为"让这个循环更安全、更高效、更可恢复"的手段。

### 第二章 · 总体架构与分层设计
剖析 monorepo 的包布局与依赖方向（schema → core/protocol → server，client 只依赖 schema 与 protocol，sdk 组合三者），解释为什么后端全面构建在 Effect 之上：服务即 Context.Service、装配即 Layer、可中断与资源安全是 agent 场景的原生需求。重点讲解 Location 模型——一个工作目录实例对应一棵 Effect 服务子树，服务器同时托管多个 Location，AppNodeBuilder 按部署选项替换实现构建整张依赖图。给出"一次用户请求的全旅程"走读。

### 第三章 · 会话引擎与主循环
OpenCode 的心脏：packages/core/src/session/ 目录（七十多个文件）与 session/runner/ 子目录。详解 drain 主循环的收件箱模型（steer 打断与 queue 排队两种投递）、advanceToStep 对控制项（手动压缩、会话迁移、空闲钩子）的处理、runStep 的步间策略、SessionStep.attempt 之内 provider 流的逐事件发布与本地工具的 fiber 并发执行。给出六种步结局（Completed/Retry/Continue/RecoverFull/Compacted/OutputLimit）的状态机与两类"陈旧结算"崩溃恢复协议。

### 第四章 · 消息模型与持久化
会话状态最终落在 SQLite：session/sql.ts 的 drizzle 表定义、消息的追加式历史、输入收件箱的事件溯源（event_sourced_session_input 迁移）、Bus 的持久化事件序列（EventTable 与 EventSequenceTable、按聚合预留序列号）。系统讲解数据库迁移体系——migration/ 目录下按时间戳命名的迁移文件、migration.gen 自动生成清单、schema.gen 一次性建表、三套 SQLite 运行时后端（bun/node/workerd）与 v1 数据迁移层，论证"可恢复"如何成为持久层的设计公理。

### 第五章 · 上下文工程与压缩
上下文窗口是 agent 最稀缺的资源。本章以 session/compaction.ts 为核心，讲自动压缩的触发判定 due 与上限计算 calculateCeiling（预留 15% 且不少于 16k 空隙）、后台预计算 precompute 利用 prompt 缓存热度提前备好摘要、被拒后的逐级收缩 deliver（85%/70%/50%/35%）、历史文本化 flattenAndDropOldest 的"从旧到新逐级降级"算法；再延伸到系统提示 system.txt、AGENTS.md 指令注入与 instruction-state 的就绪门控，把"上下文工程"总结为一条可推导的资源管理策略。

### 第六章 · 工具体系与运行时
所有工具（内置、插件、MCP）统一注册进 Tool 服务。讲注册校验（名称字符集、execute 名字保留、Standard Schema 输入契约）、snapshot 按权限产出本轮可用工具集、executeTool 的钩子管线（before/after/规范化）、直接工具与 Code Mode 元工具的双轨制——模型写一段 TypeScript 程序来编排多次工具调用以减少往返。逐一走读 shell（作业化、转后台、崩溃找回）、edit（LF 视图匹配与三级降级）、read、grep/glob 等代表工具的实现权衡。

### 第七章 · 模型接入层
OpenCode 接入几十家模型服务商的三层解耦：models.dev 元数据目录、按需加载的 provider 包（aisdk: 前缀兼容任意 AI SDK 生态）、自研的 packages/ai 协议层（providers/ 目录四十余个协议实现、route/ 统一抽象、LLMEvent 事件流建模）。详解两层重试体系（SessionRunnerRetry 的会话级决策与 route/decision 的传输级轮换）、错误分类与恢复标记（retry-full、rotate-and-retry-full、isContextOverflowFailure）、凭据存储 Credential 与 OAuth 流程。

### 第八章 · 权限与安全
权限系统只有两个原语：assert 与 assertNotDenied，规则是带通配符的（action, resource, effect）三元组列表，"缺省全拒"作为安全基线。讲规则的匹配与求值顺序、用户回复的三种语义（allow/always/reject）、已保存规则 PermissionSaved 的持久化与回放、shell 工具的命令解析授权链（ShellParse.scan → 外部目录校验 → 逐条断言）、edit 的写授权与 diff 预览、build 与 plan 两个内置 agent 在权限层面的表达差异，以及"进程边界即信任边界"的沙箱观。

### 第九章 · 配置系统
机器配置（opencode.json/jsonc）与指令配置（AGENTS.md）的双层结构。讲配置发现 discovery、解析归一化 normalize（版本迁移、旧键兼容）、层级合并与优先级规则、变量展开 config/variable、监听热更 config/watch；提炼 core 中无处不在的 State 模式（initial/editor/notify/transform/reload 四件套）如何让配置语义一致——默认值集中、修改可审计、重载可撤销；并覆盖 wellknown、workspace、managed policy 等派生机制。

### 第十章 · MCP 与插件体系
两个扩展面的同构与分工。MCP 侧：stdio 与 Streamable HTTP 双传输、连接池 pool、OAuth 接入、工具/资源/提示词三类能力向统一工具注册表的汇入、elicit 表单交互。插件侧：PluginHost 与 plugin/service 的激活代（Generation）模型、前缀差异驱动的热重载、supervisor 对插件进程的治理、hooks 契约（tool.execute.before/after 等）、插件对 system prompt、agent、command、skill 各面的编织点。论证"外部进程 + JSON-RPC"是同一问题的两个实例。

### 第十一章 · Server 与 RPC 传输
协议即代码：protocol/src/api.ts 用 effect HttpApi 声明端点组，openapi.json 自动生成，client 包由 codegen 产出、禁止手改。讲 makeRoutes 的依赖图装配（applicationServiceNodes 列出全部应用级服务节点）、独立 server 与嵌入式 routes 两种形态、中间件链（鉴权、schema 错误、Location 归属）、事件面（Bus → event-feed 订阅流、SSE/WebSocket）、服务器配对 pairing 与两层鉴权（provider 凭据与 client 连接凭据的区分）、workerd 嵌入形态。

### 第十二章 · 终端前端 TUI
用 solid-js + @opentui 在终端里渲染响应式界面的完整体系。讲 TUI 的组件分层（routes 会话路由、component 会话帧与工具渲染、prompt 输入区与自动补全）、事件订阅与本地投影（三端同构的画面）、编辑器体系（自研 editor 与 zed 集成的双轨）、对话矩阵（二十余个 dialog 的职责）、终端 UI 的独有约束（cell 网格、滚动、宽度测量、输出折叠 collapse-tool-output）与注意力系统（attention 声音提示）。

### 第十三章 · 辅助机制
支撑主循环的一圈卫星系统：ripgrep 检索适配器（原始行数据与展示/权限分离）、snapshot 快照与回滚（git 深层的影子仓库）、vcs 状态聚合与 patch 生成、worktree 多工作树管理、pty 与 persistent-pty（崩溃后可恢复的伪终端）、job 后台作业、schedule 调度、websearch 网页检索、voice 语音实时会话、filesystem search（fff）全文检索、kv 与 shared-cache 等基础设施。本章揭示"agent 的能力半径由卫星系统决定"。

### 第十四章 · 测试、构建发布与设计复盘
质量面：packages/core/test 与 packages/server/test 的测试矩阵（bus 路由、数据库迁移、codemode、credential 锁等专题测试）、fixture 与模拟后端（simulation 模式动态替换实现）、kernel 测试思想。构建面：bun build 打包、httpapi-codegen 代码生成器（compile/emitEffect/emitPromise 五个发射器、可移植性判定、命名空间迁移）、发布渠道矩阵。最后以设计复盘收束全书：这套架构的五个正确决策、三个代价与可迁移的设计原则。

### 第十五章 · 性能与资源管理
工程横切面之一。定义 agent 的三种稀缺资源（token、时间、注意力）并指出瓶颈随场景漂移；汇总全书 token 治理机制成一本全局账本（结构省 token、缓存省成本）；拆解一次输入的时延公式并给出"流式呈现兑换感知"的策略；汇总并发度治理设施（信号量、有界队列、背压）；给出内存治理的三类法则（显式上限、弱引用防缓存钉死、生命周期对齐）；区分启动与常驻两个性能场景；最后给出五步性能诊断的固定流程。

### 第十六章 · 诊断、可观测性与故障排查
工程横切面之二。以"事件即日志"确立可观测性的架构优势（Bus 落库事件就是最完整的结构化日志）；讲解 request-tracing 的跨层因果链、service-status/server-info/debug 的分级状态面；给出"症状—机制—排查路径"十大故障对照表（连接、回放、模型、权限、配置、MCP、迁移、内存）；完整描述崩溃取证的读法（遗留 running 状态、收件箱、PTY 票据）；并阐述运行时、重现、降级三层调试面与"可重现性决定排障效率"的理念。

### 第十七章 · 生态对比与适用场景
工程横切面之三（标注为作者分析）。以"形态即执行环境的选择"建立终端 agent、IDE 内嵌、IDE 原生、云托管四类形态的约束对比；归纳 OpenCode 的五条差异化特征（内核唯一三端共享、可嵌入内核、执行三角完整、上下文工程激进、开源本地优先）；给出高匹配与低匹配场景的判断框架；分析 MCP 开放协议对开源产品生态位的战略意义；最后以四问决策树收束，并总结全书那条"数学性质与稀缺资源投影为架构"的主推导线。

### 第十八章 · 全流程实战走读
时间线视角的收束章。以八个典型场景把全书机制按真实发生顺序串成走读：新项目上手的一天（启动链路、指令门控、四级预算）、一次 bug 修复的完整生命周期（plan 探索到 build 实施、diff 预览、三级降级、授权学习、压缩换入）、进程崩溃与恢复全景（两次陈旧结算、回放补历史、PTY 票据寻回）、多会话并行的工作日（worktree、标签、注意力分配、子代理预压缩）、CI 无人值守（OIDC 换 token、fail-closed 下的自动化、PR 回传）、扩展开发者的第一天（最小 MCP 服务器、插件钩子渐进、simulation 调试），再加跨天长任务的上下文管理（检查点、todo 锚定、回放重建）与贡献者从读码到 PR 的旅程两个场景。收束观察：架构的最终检验不是单一场景的表现，而是场景之间不互相拆台。

## 五、阅读前提与约定

本套文档假设读者具备基本的 TypeScript 阅读能力，但不要求懂 Effect——所有涉及 Effect 的机制（Layer、fiber、uninterruptibleMask 等）在出现处均有面向新手的解释。与已有资料的关系：doc_zh/components/ 的八篇组件文档是"是什么"层面的精炼总结，本套文档在其基础上向"为什么与如何"纵深；packages/web/src/content/docs 的官方文档回答"怎么用"，本套文档回答"为什么这样设计"；源码内的逐行中文注释回答"每一行做什么"，本套文档回答"每一段为什么存在"——四种资料各守一层，互为索引。读者若在某章遇到理解障碍，推荐的回退路径是：先看该章开头引用的组件文档或源码注释，再回到本章——纵深阅读的门槛应当被浅层资料垫底，而不是被跳过。文中行号引用（如 llm.ts:64-221）以本套文档提交时的代码为准，OpenCode 迭代很快，行号会漂移但文件与符号名相对稳定。带"推导"或"权衡"字样的小节是作者基于代码事实的工程分析，属于解读而非仓库声明；带"对照"字样的小节引用了 doc_zh/components/ 下已验证的组件文档。LaTeX 公式仅用于表达资源估算与成本模型，均在初等数学范围内。全部代码块均为说明性摘录，非完整可运行程序。
